## 2024-09-05 - Optimize inner loop word matching in reaction compilation
**Learning:** In C++, replacing repetitive `find` and boundary-check string searches inside nested loops with a precomputed extraction of words (using `std::string_view` for zero-allocation performance) significantly reduces scanning overhead. When searching for every model function within every reaction rate law, the string length and repeated scanning cost creates an O(N * M) bottleneck, where pre-extracting word tokens reduces it to near O(N + M).
**Action:** When a static text (like a rate string) is repeatedly scanned for many different substrings (like function names), extract the tokens upfront into an array of `std::string_view` to replace O(N * M) string scanning with O(M) token iterations.
