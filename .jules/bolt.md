## 2024-04-27 - Caching String Values Safely Across Loop Iterations
**Learning:** In C++, binding a temporary object to `const auto&` inside a loop extends its lifetime *only* until the end of that specific loop iteration. If you are caching that value across iterations to skip redundant map lookups, storing it as a `std::string_view` will result in a Use-After-Free, because the string's backing memory is destroyed. The compiler often reuses the same stack slot on the next iteration, which can mask the UAF and lead to a logic bug where completely different string contents at the same memory location appear "equal".
**Action:** When caching values across loop iterations where the source might be a temporary (such as from a ternary operator returning `std::string()`), always cache them by value (e.g., using `std::string`) instead of references or views, to ensure safe and correct memory lifetime tracking. The Small String Optimization makes this very fast anyway.
