## 2025-02-20 - Fix predictable temporary file names and race conditions in XMLRPC Server
**Vulnerability:** Predictable temporary file names (e.g., `temp1.bngl`) were created in the current working directory inside the XMLRPC server implementation in `parsers/ContactMap/server.py`. The sequential generation logic using an uncontrolled global lock allowed multiple concurrent requests to potentially overwrite each others files, resulting in race conditions and data corruption. Furthermore, relying on `os.remove` iterating over `glob.glob` strings allowed for insecure file deletion, and a failed file processing flow might leave undeleted files behind on the server.
**Learning:** Hardcoded, predictably sequential filenames (e.g., generated via a simple atomic integer sequence `temp{0}.bngl`) used for data staging are inherently dangerous for any multi-user or network-accessible service. It leads to race conditions or information disclosure if files persist due to errors.
**Prevention:** Use Python's built-in `tempfile` module (specifically `tempfile.mkdtemp()` or `tempfile.NamedTemporaryFile`) for securely staging files for subprocesses. Always ensure file cleanup occurs unconditionally using a `try...finally` block.
