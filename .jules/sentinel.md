## 2024-05-18 - Insecure Temporary File Management
**Vulnerability:** The ContactMap `server.py` script was generating predictable temporary file names (`temp{counter}.bngl`, etc.) directly in the current working directory, using `counter` which is a sequentially incremented integer. This created a race condition vulnerability, as an attacker could potentially guess the filename and create a symlink to a sensitive file before the server created the output, tricking the server into overwriting it (symlink attack) or exposing information. The cleanup also relied on `glob.glob` matching and sequential names, which is brittle and insecure.
**Learning:** Sequential counters and current directory placement for temporary files, especially in a server environment that processes external input, create critical security risks.
**Prevention:** Always use `tempfile.mkdtemp()` (or similar secure tempfile generation utilities like `tempfile.NamedTemporaryFile`) to create a secure, randomized temporary directory with restricted permissions. Write all temporary outputs into this secure directory. Ensure cleanup uses `shutil.rmtree` within a `try...finally` block to guarantee removal regardless of execution outcome.
